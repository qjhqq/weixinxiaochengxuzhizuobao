# 升级与迁移

> **一句话原则：升级只换「流程文件」，永远不动「你的作品」。**
> 你的作品是这四样：`我的项目/`、`miniprogram/`、`cloudfunctions/`、`00-开工/PROGRESS.md`。
> 其余文件都是可以整个替换的。

---

## 先判断：要不要升级

看两个地方：

| 看哪里 | 内容 |
|---|---|
| `00-开工/PROGRESS.md` 顶部 | `kit_version: 2.4`（你这套包的版本） |
| `README.md` 第一行 | `# 小程序开工包 v2.4`（官方最新版） |

两个数字一样 → 不用管。
`PROGRESS.md` 里的更小 → 可以升级，但**不升级也能继续做**。流程改动主要影响后面还没走的阶段，做到一半不用推倒重来。

**已经做完提审的，不要升级。** 没意义，还会打乱记录。

---

## 三种升级方式，按你的情况选

### 方式 A：新解压 + 搬四样（推荐，最安全）

1. 把新版 zip 解压到一个**新文件夹**（比如 `小程序开工包-v2.4/`）
2. 把你旧包里的这四样**复制**过去（不是移动，确认新版能跑再删旧的）：
   - `我的项目/`
   - `miniprogram/`
   - `cloudfunctions/`
   - `00-开工/PROGRESS.md`
3. 用 AI 工具打开新文件夹，说这句：

```
读一下 AGENTS.md，我升级了开工包，帮我做一次迁移检查。
```

AI 会按下面「迁移检查清单」逐条核对，把缺的补上。

### 方式 B：直接覆盖解压（快，但要先备份）

1. 先把上面四样**复制**到包外面（比如桌面新建一个 `备份/`）
2. 解压新版，选择「覆盖同名文件」
3. 确认四样还在，再删备份

> 覆盖不会删掉你的文件（解压只会覆盖同名文件），但**新版不会自动帮你合并 `PROGRESS.md`**。
> 如果新版改了字段名，旧 `PROGRESS.md` 可能读不出状态 —— 所以第 1 步的备份不能省。

### 方式 C：用 git 拉（只有你 clone 过仓库才适用）

```bash
git pull
```

`我的项目/` 和代码目录都在 `.gitignore` 里，`git pull` 不会碰它们。
唯一要手动看的是 `00-开工/PROGRESS.md`（它被跟踪，可能有冲突）。

## 迁移检查清单（AI 执行）

用户说「升级了」时，按顺序做完这五条，每条给一句话结论：

```
1. 读 00-开工/PROGRESS.md，确认 stage 和上次的产出物路径
   → 如果 stage 不是 none，作品就在，没被覆盖

2. 检查这四样是否都在：
   我的项目/  miniprogram/  cloudfunctions/  00-开工/PROGRESS.md
   → 缺哪个，问用户是不是还没到那一步（缺 miniprogram/ 通常是还没进阶段 4）

3. 旧 PROGRESS.md 缺新字段（比如 kit_version）→ 补上，值填当前包版本，不要重写整个文件

4. 对照 00-开工/阶段地图.md，看已完成的阶段有没有新增的必读文件
   （比如 v2.1 新增 08-设计参考/）→ 只补读当前阶段和下一阶段需要的，不要重读全部

5. 把 kit_version 改成新版本号，在决策记录里加一行：
   「2026-XX-XX 升级到 vX.Y」
```

**不要做的三件事**：

- 不要把旧 `我的项目/` 里的文档按新模板重写 —— 用户的记录比格式重要
- 不要因为新版多了阶段就要求回去补做 —— 只补当前阶段缺的
- 不要动 `miniprogram/` 里的任何代码，除非用户明确说要改

## 版本改动会影响什么（历史）

| 版本 | 升级影响 |
|---|---|
| v2.4 | 新增 `AGENT-开工.md`：31 KB 单文件内核，发给任何 AI（含豆包、网页版）都能直接开工，不需要解压和打开文件夹。`AGENTS.md` 开场改成「能力自检 + 自己解压」，不再把 zip 问题丢回给用户。**纯增量，不动任何产出物** |
| v2.3 | 新增 `安装技能.bat`：双击把流程装成全局 AI 技能，之后说「我要做一个微信小程序」就能开始，不再依赖这个文件夹。技能改成自包含（自带七阶段/设计/故障速查）。**不装也不影响原有用法** |
| v2.2 | 修流程漏洞、加示例项目。`PROGRESS.md` 新增 `kit_version` 字段，其余不变 |
| v2.1 | 新增 `08-设计参考/`。阶段 2 必读，已过阶段 2 的不用回头补 |
| v2.0 | 结构大改，和 v1.x 不兼容。v1.x 用户建议按方式 A 重来，只搬 `我的项目/` 和代码 |
