# 七阶段地图

> 一页看清全程。每个阶段对应 `01-阶段包/` 里一个文件。

## 全景

| 阶段 | 干什么 | 耗时 | 出门产出 | 不过门的后果 |
|------|--------|------|---------|------------|
| **0 合规** | 确认个人/企业主体能做什么、类目怎么选 | 0.5 天 | 能力清单 | 做完了上不了架 |
| **1 策略** | 北极星指标 + 四层漏斗 + MVP 砍到最小 | 0.5 天 | 产品策略 | 功能越做越多，永远上不了线 |
| **2 设计** | 页面清单 + 设计 token + 参考截图 | 1-2 天 | 页面清单、设计规范 | 边写边改样式，返工三遍 |
| **3 技术** | 技术栈定死 + 数据模型 + 云函数清单 | 0.5 天 | 数据模型 | 写着写着发现表设计错了，数据要重录 |
| **4 开发** | 一页一页做，每日循环：做一个页面 → 跑 check → 你验收 → 记进度 | 1-3 周 | `miniprogram/` 能跑的小程序 | 范围越做越大，永远上不了线 |
| **5 内容** | 首批内容库 + 冷启动素材（与 4 并行） | 持续 | 内容库 | 上线是空壳，没人留 |
| **6 提审** | 自检 → 提审 → 被拒 → 改 → 再提 | 1-3 天 | 提审记录 | 反复被拒，浪费一周 |

## 为什么是这个顺序

**合规在最前**，因为它是唯一一个「做错了要推倒重来」的环节。类目选错、主体能力不够，代码写得再好也没用。

**设计在开发前**，因为 UI 返工的成本是逻辑返工的 3 倍。样式先定死，开发时只填内容。

**内容与开发并行**，因为内容是最容易被拖到最后、然后上线变空壳的部分。

## 门（gate）的定义

每个阶段的门 = 一组可以**客观打勾**的检查项。不是「感觉差不多了」，是「文件存在 + 条目齐全」。

门的检查由 AI 执行，格式：

```
阶段 X 出门检查：
✅ 项 1
✅ 项 2
❌ 项 3 → 我来补，5 分钟
结论：可以进阶段 X+1 / 还差一项，补完再走
```

## 时间预期（真实项目，一个人 + AI）

| 你的情况 | 现实预期 |
|---------|---------|
| 完全不会代码，每天 2 小时 | 4-6 周到能提审 |
| 会一点，周末集中做 | 2-3 周 |
| 会前端，全职 | 1 周内 |

**不要承诺「三天上线」**。三天能做出 demo，做不出能过审的产品。对用户也这么说，别画饼。
