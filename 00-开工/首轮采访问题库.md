# 首轮采访问题库

> AI 用。目标是**用最少的提问拿到足够开工的信息**，不是做用户调研。
> 原则：能自己查的别问，能猜的给默认值让他改，只有「只有他知道」的才问。

---

## 第一轮（4 题，必问）

### Q1 给谁用

```
这个小程序主要给谁用？
A. 我自己 / 家人（自用工具）
B. 某一类职业人群（比如：健身教练、房东、花店老板）
C. 某个社区 / 学校 / 小区
D. 我的客户（我开店或接单）
E. 我还没想清楚
```

### Q2 解决什么麻烦

如果他 Q1 选了具体人群，**你现场生成 3 个方向**，格式：

```
这类人最烦的三件事，你看哪个最像你想做的：
A. 【场景1】他们现在用【土办法】，问题是【痛点】
B. 【场景2】…
C. 【场景3】…
D. 都不是，我自己说（一句话就行）
```

如果 Q1 选了 E，改用下面的**方向生成器**。

### Q3 主体类型

```
你打算用什么主体注册小程序？
A. 个人（免费，但功能受限）
B. 个体户（有营业执照）
C. 公司
D. 不知道这有什么区别
```

> 选 A 或 D → 阶段 0 必须重点讲能力边界，别跳过。
> 选 B/C → 提醒他营业执照的**经营范围**要和类目对上，这是最常见的拒审原因。

### Q4 技术底子

```
你写代码到什么程度？
A. 完全不会，只会用电脑
B. 看得懂、能改几行
C. 会前端（HTML/CSS/JS）
D. 会全栈，能自己搭后端
```

> 这决定后面所有解释的颗粒度，也决定技术栈推荐：
> A/B → 原生 + 云开发，一切从简，不引入框架；
> C → 原生 + 云开发，可以讲组件化和状态管理；
> D → 直接讲架构取舍，可以聊 CI、多端。

## 第二轮（按需，最多问 3 个）

只在信息真的不够时问。**不要为了完整而问**。

| 场景 | 问什么 | 为什么 |
|------|--------|--------|
| 他说要「AI 生成内容」 | 内容是**预置的**还是**每次现生成**的？ | 现生成 = 生成式 AI 类目 = 个人主体过不了 |
| 他说要「用户之间互动」 | 用户之间需要看到彼此吗？ | 需要 → 涉及内容审核，成本和合规都翻倍 |
| 他说要「收钱」 | 卖实物、卖服务、还是卖虚拟内容？ | 个人主体不能开虚拟支付；实物要走微信支付商户号 |
| 他提到某个具体行业 | 你在这个行业里，最想让外行知道的三件事是什么？ | 这是他的护城河，比任何 AI 生成的需求都值钱 |
| 他说「要做大」 | 前 100 个用户你打算从哪来？ | 答不上来 = 先别做，去做内容 |
| 他时间很紧 | 你每周能投入几小时？ | 决定 MVP 砍到什么程度 |

## 方向生成器（用户说「没想法」时用）

给 **3 个方向**，每个用固定三段式：`谁` + `什么场景` + `为什么愿意再用一次`。
必须满足：**个人主体能做、不需要 AI 生成、不需要用户之间互动、一个人两周能做完**。

模板：

```
A.【记录类】给【人群】记【某样数据】，因为他们现在用【微信收藏/纸质本】，
   记完从来不看。愿意再来的理由：【自动生成月报/趋势对比】。
B.【工具类】帮【人群】算【某个他们算不清的东西】，比如【例子】。
   愿意再来的理由：【每次场景重复出现，且结果比问人快】。
C.【查询类】把【某个分散在各处的信息】整理成一个能搜的库，
   比如【例子】。愿意再来的理由：【信息会更新，收藏不如进来查】。
```

三个方向里**必须有一个是他行业相关的**（如果他提过行业），另外两个可以跨行业举例。

---

## 采访时的说话方式

**要**：
- 「我先问你四个问题，一两分钟，问完我就知道该怎么带你做了。」
- 「这题不确定就选最后一个，我按最常见的情况给你默认方案。」
- 每个问题后面加一句「为什么问这个」，一句话，让他知道不是审问。

**不要**：
- 「请详细描述您的需求」（他描述不出来）
- 一次抛 8 个问题（他会关掉窗口）
- 问完不给反馈就开始要下一个信息（他不知道自己答得对不对）

## 采访后的收尾（固定格式，8 行以内）

```
看明白了。三句话给你判断：

能做。记录类 + 个人主体，合规上没硬伤。
最大风险是留存 —— 记完不看是这类产品的通病，得靠"月报"把人拉回来。
最小版本砍到 5 个页面：首页 / 记录 / 记录详情 / 我的 / 隐私政策。

已经写进 我的项目/01-项目简报.md。
下一步是阶段 0：确认你个人主体到底能做哪些功能，这个必须先定，不然白做。
第一个问题 ——（继续问）
```
