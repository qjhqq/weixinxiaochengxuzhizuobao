# check.js 怎么用

> 一个零依赖的体检脚本，专查「提审前必踩的坑」。不是代码风格检查。

## 跑起来

```bash
node check.js                     # 检查当前目录
node check.js ./miniprogram       # 检查指定目录
node check.js --json              # 输出 JSON，方便 AI 解析
```

需要 Node 14+。不需要 `npm install`。

## 它查什么

| 规则 | 级别 | 为什么重要 |
|------|------|-----------|
| `wxss-no-css-var` | 必须改 | WXSS 不支持 `var(--x)`，会让整页样式失效 |
| `page-class-misuse` | 必须改 | 全局 `.page` 带负边距，非沉浸式页面内容会被导航栏挡住 |
| `no-web-view` | 必须改 | 个人主体用 web-view 必被拒 |
| `hardcoded-secret` | 必须改 | 密钥硬编码，开源或分享时直接泄露 |
| `app-json-invalid` / `page-missing` | 必须改 | 注册了页面但文件不存在，白屏 |
| `image-too-large` | 建议改 | 单图 > 200KB 会报警告 |
| `ad-law-words` | 建议改 | 广告法违禁词，审核会挑 |
| `console-left` / `todo-left` | 提示 | 提审前清理 |
| `assets-size` | 提示 | 主包 2MB 上限，图片多就超 |

## 怎么读报告

```
必须改（5）   → 提审前必须清零，否则大概率被拒或线上出 bug
建议改（1）   → 看情况，能改就改
提示（3）     → 知道就行
```

退出码：`0` 无错误，`1` 有错误。可以挂到 CI 或提审前的脚本里当门禁。

## 误报了怎么办（忽略机制）

工具一旦误报两次，人就再也不跑了。所以给了两个开关，**都只关掉「那一条」，不关掉整个工具**。

### 方式一：行内注释（推荐，最不容易忘）

写在报错的那一行同一行，或紧挨着的上一行：

```html
<!-- check-ignore page-class-misuse -->
<view class="page">这个页面确实是沉浸式的</view>
```

```css
/* check-ignore wxss-no-css-var */
```

```js
// check-ignore hardcoded-secret
const demo = 'sk-xxxxxxxxxxxxxxxxxxxx';
```

只写 `check-ignore` 不跟规则名 = 这一行所有规则都不报。

### 方式二：项目根目录 `.checkignore`

```gitignore
# 整个文件不检查
pages/legacy/*

# 全局关掉某条规则（谨慎，等于放弃这条检查）
ad-law-words

# 只关某个文件的某条规则
pages/index/index.wxml:page-class-misuse
```

报告里会显示 `已忽略：N 条`，不会偷偷吞掉。

### 什么时候才该忽略

- **该忽略**：确认过是误报（比如页面真的是 `navigationStyle: custom`），或者历史页面这次不重构。
- **不该忽略**：因为改起来麻烦。忽略掉的每一条，提审时都可能被人挑出来。

忽略条目建议写清原因，`#` 后面写：

```gitignore
pages/legacy/*        # 二期要重写，一期先上线
```

## 给 AI 的用法

在 `AGENTS.md` 的纪律里已经写了：**每轮实质改动后跑一次，把结果贴出来再说「改完了」**。

如果你想手动要求：

```
跑一遍 node 04-工具/check.js ./miniprogram，把「必须改」逐条解释根因并修掉，
修完再跑一次确认清零。
```

## 它不查什么

- 逻辑 bug（要靠真机点）
- UI 细节（要靠截图）
- 类目和资质（要靠人核对官方文档）
- 云函数部署状态（要靠控制台看）

**体检通过 ≠ 能上线**，只是「没有已知的硬伤」。
