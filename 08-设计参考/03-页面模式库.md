# 页面模式库

> 12 种常见页面的骨架。写页面前先在这里找到对应模式 —— **不要从空白页开始想**。
> 每种都写清：什么时候用、结构长什么样、关键尺寸、最容易做错的地方。

---

## 1. 工具型首页（功能宫格）

**适用**：功能不超过 8 个、每个功能都有独立页面。记账、计算器、健康记录、管理后台。

**骨架**

```
┌──────────────────────────┐
│  你好，今天 10月31日        │  ← 问候区，可省
│                          │
│  ┌────┐ ┌────┐ ┌────┐ ┌────┐ │
│  │icon│ │icon│ │icon│ │icon│ │  ← 4 列，每格 2 行文字
│  │记一笔│ │看趋势│ │定目标│ │ │
│  └────┘ └────┘ └────┘ └────┘ │
│                          │
│  ┌────────────────────┐  │  ← 主卡片：今天最该看的一个数
│  │  今日支出  ¥128.50   │  │
│  │  比昨天少 12%        │  │
│  └────────────────────┘  │
└──────────────────────────┘
```

**尺寸**

- 宫格：4 列，每格宽 `(750 - 64) / 4 ≈ 171rpx`，图标 56rpx，文字 24rpx
- 单行 4 个最多 2 行；超过 8 个功能改用「更多」页，不要做成 3 行
- 宫格区上下 padding 40rpx

**坑**

- 图标尺寸不统一 → 视觉立刻乱。全部 56rpx 画布，图形本身留 8rpx 内边距
- 文字超过 4 个字会挤 → 用 2 行或改成 3 个字（「记一笔」而不是「记录一笔支出」）
- 宫格之间没有留白，挤成一坨 → 用 `gap: 16rpx` 或均分

## 2. 内容型首页（卡片流）

**适用**：文章、课程、案例、商品。用户来是为了「看」。

**骨架**

```
┌──────────────────────────┐
│  ┌────────────────────┐  │
│  │      封面图 16:9     │  │  ← 图在上
│  │                    │  │
│  ├────────────────────┤  │
│  │ 标题最多两行，28rpx  │  │
│  │ 摘要 24rpx 灰，两行  │  │
│  │ #标签  · 3 分钟前    │  │
│  └────────────────────┘  │
│  ┌────────────────────┐  │  ← 卡片间距 24rpx
│  │      封面图          │  │
```

**尺寸**

- 卡片圆角 16rpx，图片上圆角跟随，用 `border-radius:16rpx 16rpx 0 0`
- 图片比例固定：文章 16:9，商品 1:1，课程 4:3。**不要让它自适应高度**
- 标题 `-webkit-line-clamp:2`，摘要同理

**坑**

- 封面图不固定高度 → 加载完成后布局跳动，用户正在点的位置就变了（CLS）
- 标题长度不一却居中 → 一律左对齐
- 卡片里要塞「阅读量 / 点赞 / 评论」三个数字 → 只留一个有意义的，其余删

## 3. 服务型首页（Banner + 金刚区 + 推荐）

**适用**：预约、门店、医疗、教育机构。要同时表达「我们是谁」和「能干什么」。

**骨架**

```
┌──────────────────────────┐
│  轮播 Banner（3:1 或 2:1）  │  ← 高度固定，最多 3 张
├──────────────────────────┤
│  ┌──┐ ┌──┐ ┌──┐ ┌──┐      │  ← 金刚区，5 个以内
│  └──┘ └──┘ └──┘ └──┘      │
├──────────────────────────┤
│  为你推荐           更多 >  │  ← 区块标题 + 出口
│  ┌────┐ ┌────┐            │
│  │卡片 │ │卡片 │            │
└──────────────────────────┘
```

**尺寸**

- Banner 高度 320rpx（比例 2:1），左右不留边距或留 32rpx，二选一且全站统一
- 金刚区图标 72rpx，文字 24rpx，一行 5 个
- 区块标题 36rpx / 600，右侧「更多」24rpx 灰

**坑**

- Banner 放 5 张以上 → 用户根本不会翻到第 4 张，浪费首屏
- 金刚区写成 2 行 10 个 → 首屏被功能入口吃满，看不到任何内容
- 「更多」按钮只有文字没有箭头，用户不知道能点

## 4. 列表页（带筛选吸顶）

**适用**：数据量 20 条以上，需要按条件看。

**骨架**

```
┌──────────────────────────┐
│  全部 ▾ │ 最新 ▾ │ 筛选 ⚙  │  ← 吸顶，高 88rpx
├──────────────────────────┤
│  左图 88rpx │ 标题        │
│            │ 副信息 · 时间 │  ← 行高至少 128rpx
├──────────────────────────┤
│  左图       │ 标题        │
├──────────────────────────┤
│        加载中…            │  ← 分页指示，不要用弹窗
```

**要点**

- 筛选项不要超过 3 个，超过就收进「筛选」面板
- 行高 ≥ 128rpx，否则手指点不准
- 整行可点，`hover-class` 给整行一个 `#F7F8FA` 底色
- 分页：`onReachBottom` 加载下一页，底部文案三态：加载中 / 没有更多了 / 加载失败点击重试

**坑**

- 列表项没做 key（`wx:key`）→ 删除某项后 UI 错乱
- 下拉刷新和 `scroll-view` 同时用，两套滚动打架 → 页面级滚动就用 `onPullDownRefresh`，不要套 `scroll-view`
- 空态只在第一页判断，第二页返回空时界面卡住

## 5. 详情页（图文 + 底部操作栏）

**适用**：商品、文章、课程、记录详情。

**骨架**

```
┌──────────────────────────┐
│  主图 / 头图（可滑动）      │
│  标题 40rpx / 600         │
│  价格或关键指标  52rpx     │
│  ─────────────────────   │
│  正文段落 28rpx / 1.75    │  ← 长文行高放到 1.75
│  …                       │
│  （内容区底部留 200rpx）    │
├──────────────────────────┤
│  ☆收藏   │   立即预约      │  ← 固定底栏
└──────────────────────────┘
```

**要点**

- 正文行高 1.75，段间距 24rpx，段首不缩进（移动端不缩进）
- 底栏左侧图标区宽 120rpx，右侧主按钮占满剩余
- 页面容器 `padding-bottom: 200rpx` 给底栏让位，否则最后一段永远被挡住

**坑**

- 富文本 `rich-text` 里的图片不会自适应，要预处理：`<img style="max-width:100%">`
- 底栏用 `position:fixed` 但没算安全区 → iPhone 上按钮贴着底部横条
- 详情页没有 loading 骨架，白屏 1 秒像卡死

## 6. 表单页（分组 + 底部提交）

**适用**：资料填写、预约信息、反馈、报修。

**骨架**

```
┌──────────────────────────┐
│  基本信息                  │  ← 分组标题 24rpx 灰，左边距 32rpx
│  ┌────────────────────┐  │
│  │ 姓名        请输入   │  │  ← 行高 104rpx，label 左，input 右
│  │ ──────────────────  │  │
│  │ 手机号      请输入   │  │
│  │ ──────────────────  │  │
│  │ 预约时间    请选择 > │  │  ← 选择类右侧带箭头
│  └────────────────────┘  │
│  其他                      │
│  ┌────────────────────┐  │
│  │ 备注（多行）         │  │
│  └────────────────────┘  │
├──────────────────────────┤
│         提交             │
└──────────────────────────┘
```

**要点**

- 单行高度 104rpx，分割线只在行之间（`border-bottom`，最后一行去掉）
- label 固定宽 160rpx，右对齐或左对齐但要全站一致
- 必填项用红色星号，且**提交时校验**，不要边输边报红
- 提交按钮在表单末尾（内容不满一屏时），不要固定悬浮 —— 会挡住最后一行
- 提交后禁用按钮 + 文案变「提交中…」，防重复提交

**坑**

- 用 `input` 的 `placeholder` 当 label → 输入后用户忘了这行填的是什么
- 手机号、身份证没设 `type`，用户要手动切键盘
- 校验失败只弹 toast，不定位到出错的行

## 7. 结果页（成功 / 失败 / 待审核）

**适用**：支付完成、提交成功、预约成功、审核中。

**骨架**

```
┌──────────────────────────┐
│                          │
│         ✓（120rpx）       │  ← 图标，绿/红/橙
│      提交成功             │  ← 40rpx / 600
│   我们会在 24 小时内联系你  │  ← 24rpx 灰，最多两行
│                          │
│  ┌────────────────────┐  │  ← 信息卡：把关键信息摊开
│  │ 预约号   A1024      │  │
│  │ 时间     10-31 15:00│  │
│  └────────────────────┘  │
│                          │
│     [查看详情] [返回首页]   │  ← 主 + 次
└──────────────────────────┘
```

**要点**

- 三种状态共用一个页面，用 `status` 参数切换图标、颜色、文案、按钮
- 一定要给**两个出口**：看详情、回首页。只给「返回」用户会迷路
- 信息卡只放 2-3 条真正需要的，不要把所有字段复述一遍

**坑**

- 成功页停 3 秒自动跳走 → 用户来不及截图，且跳转后无法返回
- 失败页只写「操作失败」→ 必须写原因 + 一条可操作建议
- 用 `wx.redirectTo` 而不是 `navigateTo`，否则用户能返回提交页重复提交

## 8. 个人中心

**骨架**

```
┌──────────────────────────┐
│  (头像72) 昵称            │  ← 深色/主色背景区，高 280rpx
│           手机号 138****  │
├──────────────────────────┤
│  我的预约        3  >     │
│  我的收藏        8  >     │
│  意见反馈           >     │
│  ─────────────────────   │
│  隐私政策           >     │
│  关于我们           >     │
└──────────────────────────┘
```

**要点**

- 头部用主色或深色背景，是整页唯一的「视觉锚点」
- 功能列表分两组：业务（预约、收藏）+ 平台（隐私、关于）
- 每行高 112rpx，右侧箭头 24rpx `#C8C8C8`

**坑**

- 未登录时没有态 → 头像区要显示「点击登录」
- 隐私政策入口藏太深会被审核挑（必须在两跳内可达）

## 9. 搜索页

**骨架**

```
┌──────────────────────────┐
│  [🔍 搜索框        取消]  │  ← 吸顶
├──────────────────────────┤
│  历史搜索            清空  │
│  [关键词] [关键词]        │
│  热门搜索                 │
│  [关键词] [关键词]        │
└──────────────────────────┘
```

**要点**

- 历史记录存 `wx.setStorageSync`，最多 10 条，可清空
- 空关键词时展示历史 + 热词；有输入时实时展示候选
- 搜索框高度 72rpx，圆角 999rpx，底色 `#F2F3F5`

**坑**

- 每次输入都请求接口 → 加 300ms 防抖
- 没有「无结果」态 → 要有空态 + 建议关键词

## 10. 记录 / 订单列表（状态分段）

**骨架**

```
┌──────────────────────────┐
│  全部 │ 待付款 │ 已完成    │  ← 分段器，吸顶
├──────────────────────────┤
│  单号 A1024      待付款   │
│  ┌────┐ 商品名           │
│  │ 图 │ ¥128   ×1        │
│  └────┘                 │
│           [取消] [去支付] │  ← 操作按钮右下
└──────────────────────────┘
```

**要点**

- 状态用颜色区分：待处理橙 `#FF976A`、完成灰、失败红
- 操作按钮每行最多 2 个，主操作在右
- 分段器切换用 `data-status` + 重新请求，不要前端过滤全量

## 11. 预约页（日历 + 时段）

**骨架**

```
┌──────────────────────────┐
│  10月  ◀  2026  ▶        │
│  一二三四五六日            │
│   1  2  3  4  5  6  7    │  ← 可约 / 约满 / 不可约 三态
│  ─────────────────────   │
│  上午  [09:00] [09:30]   │  ← 时段栅格，3-4 列
│  下午  [14:00] [14:30]   │
└──────────────────────────┘
```

**要点**

- 日期三态必须视觉可分：可选（白底黑字）、约满（灰字 + 划线）、不可选（浅灰）
- 时段按钮最小 120rpx × 72rpx，一行不超过 4 个
- 选中态用主色实心，未选中用浅底 `#F5F6F8`

**坑**

- 只禁用「今天之前」，忘了禁用「已过时间点」（今天 10 点仍能约 9 点）
- 时区/跨月边界没处理，用户选到 31 号跳到下个月

## 12. 空态与骨架屏

**空态三件套**：图标 + 一句人话 + 一个出口。

```
┌──────────────────────────┐
│         （插画 240rpx）    │
│      还没有预约记录        │
│   预约后会在这里看到进度     │
│        [ 去预约 ]          │
└──────────────────────────┘
```

**骨架屏**：首屏加载超过 300ms 就必须有，否则用户以为白屏卡死。

```css
.skeleton {
  background: #F2F3F5;
  border-radius: 8rpx;
  animation: sk 1.2s ease-in-out infinite;
}
@keyframes sk {
  0%   { opacity: 1; }
  50%  { opacity: .5; }
  100% { opacity: 1; }
}
```

**坑**

- 空态写「暂无数据」→ 用户不知道是没数据还是出错了
- 骨架屏的尺寸和真实内容不一致 → 加载完成后跳一下

## 其他页面的最短建议

| 页面 | 一句话 |
|---|---|
| 设置页 | 分组 + 开关右对齐，危险操作（退出、注销）单独一组放最底，红色文字 |
| 会员卡 | 卡面是唯一的视觉重点，权益列表用勾选图标，不要用 emoji |
| 多步流程 | 顶部步骤条最多 4 步，超过就用「第 2 步 / 共 5 步」纯文字 |
| 长文阅读 | 正文 32rpx / 行高 1.8，段间距 32rpx，图片满宽圆角 12rpx |
| 扫码结果 | 结果优先：先给结论（可用/不可用），再给详情 |
| 地图附近 | 地图占 60% 高度，列表用半屏面板从底部拉起，不要并排 |
