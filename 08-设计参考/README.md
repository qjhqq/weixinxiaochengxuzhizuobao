# 设计参考库

> **给 AI 读的**。写页面之前先读这一层，别凭感觉排。
> 这里没有一张别人的截图，全是能直接抄进代码的东西。

---

## 为什么不放截图

三个原因，都很硬：

1. **版权**。别人小程序的界面是别人的作品，批量截图再公开分发，属于复制他人作品。MIT 协议要求整个仓库可被商用分发，装不下这些东西。
2. **抓不到**。小程序不是网页，没有 URL 可爬，要在微信里跑起来才能截图。批量抓等于逆向客户端，违反微信的开发者协议。
3. **对模型没用**。截图是像素，模型看不到里面的 `padding: 24rpx`、`border-radius: 16rpx`、`box-shadow`。你给它 100 张图，它仍然在猜尺寸 —— 而尺寸才是「看起来专不专业」的分水岭。

所以这一层给的是**结构、尺寸、颜色、可复制代码**。AI 拿到这些能直接写对，拿到截图只能编。

## AI 的标准动作

到阶段 2，按这个顺序做，不要跳：

1. 读 `01-设计原则.md`，确认这个品类有没有硬约束（医疗不能花哨、工具不能可爱）。
2. 问用户调性。用户说不出来，就从 `04-配色方案.md` 里挑三套贴给他选，**别让他描述颜色**。
3. 按 `02-设计token.md` 把数值定死，写进 `app.wxss` 顶部注释块 + 具体类。
4. 每个页面先在 `03-页面模式库.md` 里找到对应模式，按骨架写，再按 `05-组件配方.md` 取组件。
5. 写完跑 `node 04-工具/check.js .`，它会抓出 `var(--x)` 这类会让整页样式失效的写法。

## 一条纪律

**不要在页面里写裸数值。**

```css
/* 不要 */
.card { margin: 23rpx; border-radius: 11rpx; }

/* 要 */
.card { margin: 24rpx; border-radius: 12rpx; }
```

不是强迫症。裸数值意味着每个页面各写各的，20 个页面之后圆角有 7 种、间距有 11 种，
看起来就像三个不同的人拼起来的 —— 这是「廉价感」最主要的来源，比配色选错更致命。
