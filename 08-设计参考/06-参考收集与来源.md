# 参考收集与来源

> 这一页解决一个真实的矛盾：**你想让 AI 照着好作品做，但好作品不能直接搬进仓库。**
> 下面是三条合规路径，和它们各自的边界。

---

## 为什么别人的截图不能进仓库

| 问题 | 说明 |
|---|---|
| 版权 | 小程序界面是开发者的作品（美术、布局、文案都可能受保护）。截图再公开分发属于复制他人作品。这个仓库是 MIT，允许任何人商用，装不下这类内容 |
| 协议 | 小程序没有公开 URL，要在微信里运行才能截图。批量获取等于逆向客户端，违反《微信开放平台开发者服务协议》 |
| 著作权邻接 | 界面里的品牌 Logo、商品图、人像还有单独的肖像权与商标权 |
| 技术 | 截图是像素。模型看不到 `padding: 24rpx`、`box-shadow: 0 4rpx 16rpx`、`line-height: 1.55`，只能猜。**猜出来的尺寸 90% 是错的** |

最后一条最要命 —— 就算不计版权，喂截图给模型的效果也比喂数值差一大截。

---

## 路径 A · 用户自己看，AI 本地参考（不入库）

这是最贴近「照着某家做」的做法，而且完全合规：**截图只存在用户自己的电脑上，不进 Git。**

### 做法

1. 在项目根目录建一个 `_参考/` 文件夹
2. 用户把喜欢的小程序截图丢进去，命名说明意图：

```
_参考/
├── 01-首页-想要这种宫格密度.png
├── 02-详情页-底部按钮这样放.png
└── 03-表单-分组方式.png
```

3. `.gitignore` 里已经有 `_参考/`（见下面），不会被提交
4. 对 AI 说：

```
读 _参考/ 里的三张图，只提取这几件事：
字号层级、间距密度、圆角大小、卡片是阴影还是描边。
不要照抄配色和文案，只把这几个参数写进 08-设计参考/02-设计token.md 的数值表。
```

**关键在最后一句。** 不说「只提取参数」，模型会写出一堆「蓝色渐变、圆角、现代感」的废话。

### 边界

- 只能自己看，不能 commit，不能放进 Release，不能进抖音素材
- 不要指望 AI 从截图反推出精确 rpx —— 它给的是「偏大/偏小」这种相对判断，最终数值由 `02-设计token.md` 兜底

## 路径 B · 装开源组件库，直接读代码

这是**唯一能拿到精确数值**的来源：源码里就是 `padding: 32rpx`。

| 库 | 归属 | 许可证 | 适合 |
|---|---|---|---|
| [WeUI](https://github.com/Tencent/weui-wxss) | 腾讯官方 | MIT（含第三方组件，各自协议） | 想要「跟在微信里长一样」 |
| [Vant Weapp](https://github.com/youzan/vant-weapp) | 有赞 | MIT | 电商、后台类，组件最全 |
| [TDesign Miniprogram](https://github.com/Tencent/tdesign-miniprogram) | 腾讯 | MIT | 想要设计规范成体系、有官方 Sketch/Figma |

装法（以 Vant 为例）：

```bash
npm i @vant/weapp -S --production
```

然后在 `app.json` 里按需引组件，或在 `pages/xxx.json` 里局部引。

### 让 AI 读它们的方式

```
npm 装好 vant 之后，去 node_modules/@vant/weapp/button/ 读源码，
把它的尺寸、圆角、字号整理成一张表，对照 08-设计参考/02-设计token.md，
告诉我有哪几处不一致、建议采用哪一边。
```

**不要**让 AI 直接抄整套库 —— 300KB 包体换不来 20% 的观感提升，自己写 13 个组件就够了（见 `05-组件配方.md`）。

## 路径 C · 官方设计指南（引用要点，不整篇搬）

| 微信小程序设计指南 | <https://developers.weixin.qq.com/miniprogram/design/> | 读，提炼成自己的话。**不要整段复制** |

引用纪律：如果要在文档里引用官方原文，**注明来源 + 抓取日期**，并加一句
「规则可能变更，提审前以官方最新文档为准」。否则半年后有人照着过时规则做，会觉得这份包在害人。

## 怎么找到「值得参考的作品」

不给具体公司名单（会过时，也有推荐嫌疑），给方法：

**在微信里搜这些品类词，按「小程序」筛选，看前 5 个：**

```
记账  健身  挂号  点单  预约  课程  体检报告  视力  排班
```

**看四个东西，别看好不好看：**

1. **首屏塞了几个信息块** —— 决定你的信息密度档位
2. **主操作在哪** —— 底部固定 / 页面中部 / 顶部
3. **列表行高** —— 128rpx（松）/ 104rpx（中）/ 88rpx（密）
4. **空态写什么** —— 抄它的语气，这是最省力的文案参考

**不要看**：配色（品牌属性太强，抄了不像）、插画（多数是买的素材，抄不了）、动效（实现成本高、收益低）。

## 记一笔：这个仓库里哪些是原创

明确一下边界，方便别人引用时知道分寸：

| 内容 | 来源 |
|---|---|
| `01`–`05` 全部文字与代码 | 本项目原创，MIT |
| 尺寸数值（28rpx、32rpx、16rpx 等） | 行业通用值，不构成独创性，任何项目都在用 |
| 提到的开源库名称与许可证 | 事实性信息，引用自各自仓库的 LICENSE |
| 官方规范要点 | 转述，已注明出处与日期 |

如果发现本仓库有内容侵犯了你的权益，开 issue，我删。
