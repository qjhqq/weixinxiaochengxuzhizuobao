# 设计原则

> 这一页只回答一件事：**为什么有些小程序一看就很贵，有些一看就是外包 800 块。**
> 差别不在配色，在下面这些数值和取舍上。

---

## 一、六条硬约束（违反即丑，没有例外）

### 1. 一屏只有一个主按钮

同屏出现两个同等重量的实心主色按钮，用户就不知道该点哪个，视觉也会立刻糊掉。

```css
/* 主操作：实心、主色、满宽或右对齐 */
.btn-primary   { background:#07C160; color:#fff; }
/* 次操作：描边或浅色底，永远比主按钮轻一档 */
.btn-secondary { background:#fff; color:#07C160; border:1rpx solid #07C160; }
/* 次要操作其实可以只做文字链 */
.btn-text      { background:transparent; color:#666; }
```

### 2. 正文不小于 28rpx

换算过来大概是 14px。26rpx 在 iPhone 上还勉强，到安卓 1080P 屏就发飘。
40 岁以上用户为主的品类（医疗、政务、老年关怀），正文直接上 32rpx。

### 3. 点击区域不小于 88rpx × 88rpx

等于 44pt，这是苹果和微信都建议的最小触摸目标。
常见错误：图标按钮只做了 32rpx 的图标大小，实际点击区也只有 32rpx，用户点十次中三次。

```css
.icon-btn { width:88rpx; height:88rpx; display:flex; align-items:center; justify-content:center; }
.icon-btn .icon { width:40rpx; height:40rpx; }  /* 视觉小，点击区大 */
```

### 4. 文字对比度 ≥ 4.5:1

白底上 `#999` 的对比度约 2.8，**不合格**，老年人看不清，也是无障碍问题。

| 用途 | 颜色 | 白底对比度 | 判定 |
|---|---|---|---|
| 主文字 | `#1A1A1A` | 17.4 | 合格 |
| 次文字 | `#5A5A5A` | 7.6 | 合格 |
| 辅助说明 | `#8A8A8A` | 3.9 | 仅限 32rpx 以上 |
| 占位符 | `#B0B0B0` | 2.6 | 只在输入框内可接受 |
| 禁用态 | `#C8C8C8` | 1.9 | 仅配合「不可点」的明确信号 |

### 5. 左右边距固定 32rpx

页面内容左右各 32rpx，卡片内部左右 32rpx，卡片之间 24rpx。
不要这个页面 20、那个页面 30 —— 滑动时内容会左右跳，这是最容易被察觉的低级错误。

### 6. 阴影只朝下

```css
/* 对：光源在上，阴影向下扩散 */
box-shadow: 0 4rpx 16rpx rgba(0,0,0,0.06);
/* 错：四周均匀 */
box-shadow: 0 0 20rpx rgba(0,0,0,0.15);
/* 错：阴影太重，像 2013 年的拟物 */
box-shadow: 0 8rpx 24rpx rgba(0,0,0,0.35);
```

颜色用 `rgba(0,0,0,.06)` 这一档，超过 `.12` 就开始脏。

## 二、八个「廉价感」来源

改掉这八个，观感能提升一大截，而且不需要重做设计。

| # | 症状 | 改法 |
|---|---|---|
| 1 | 圆角混用（8/12/16/20 都有） | 全站只用两档：卡片 16rpx，按钮/标签 12rpx 或全圆 999rpx |
| 2 | 字号跳档（22→24→25→27） | 固定 6 档：24 / 28 / 32 / 36 / 40 / 52 |
| 3 | 图标风格混用（线性 + 面性 + emoji） | 只用一套，线宽统一 2rpx，尺寸统一 40rpx |
| 4 | 纯黑 `#000` 大面积背景 | 深色用 `#111`，纯黑只用于小面积文字 |
| 5 | 卡片投满屏阴影 | 要么阴影 0.06，要么用 1rpx 描边，二选一 |
| 6 | 每个标题带彩色竖条装饰 | 只保留一档，且只在二级标题用 |
| 7 | 渐变滥用（按钮、背景、文字全渐变） | 一屏最多一处渐变，通常给主视觉图 |
| 8 | 长文本居中排版 | 超过两行的段落一律左对齐 |
| 9 | 空状态只有一个「暂无数据」 | 图标 + 一句人话 + 一个出口按钮 |
| 10 | 弹窗遮罩太浅 | `rgba(0,0,0,.5)`，低于 .35 内容会透出来 |

## 三、拇指区

小程序里 80% 的操作发生在单手拇指范围内。

```
┌─────────────────────┐
│   ← 顶部：只放标题，别放操作   │  ← 单手够不到
│                     │
│   中部：放内容，可以放次要操作  │  ← 勉强够到
│                     │
│  底部：主操作全放这里          │  ← 最舒服
└─────────────────────┘
```

所以：

- 主按钮默认放**底部固定栏**，不放页面中部
- 底部固定栏必须留安全区：`padding-bottom: calc(24rpx + env(safe-area-inset-bottom))`
- 列表的行内操作（删除、编辑）尽量用左滑，不要放在顶部
- 返回按钮交给系统导航栏，除非你确实要做自定义导航

## 四、信息密度

小程序屏幕小，一屏能做的事有限。三个密度档，先选档再排：

| 密度 | 单屏可容纳 | 适用 |
|---|---|---|
| 疏（每屏 3-5 个信息块） | 大图卡片、大标题、留白多 | 内容型、品牌型、课程详情 |
| 中（每屏 6-8 行） | 标准列表、表单 | 绝大多数工具、服务、电商 |
| 密（每屏 10 行以上） | 表格、明细、账单 | 记账、后台类、数据类 |

**最常犯的错**：把「密」的信息塞进「疏」的排版 —— 比如账单明细用了大卡片 + 大留白，
一屏只能看三行，用户要滑十屏。反过来也一样糟。

## 五、品类约束

定调性之前先看这一行，有些品类没有选择权：

| 品类 | 不能做的 | 必须做的 |
|---|---|---|
| 医疗 / 健康 | 高饱和撞色、动效夸张、卡通插画 | 留白充足、字号偏大、免责声明位置固定 |
| 政务 / 公共服务 | 深色模式、实验性排版 | 高对比、字号 32rpx 起、层级极简 |
| 金融 / 记账 | 花哨渐变、拟物图标 | 数字等宽、金额千分位、负数用绿（中国习惯跌绿） |
| 儿童 / 教育 | 密集信息、细灰字 | 大圆角、大按钮、动效有反馈 |
| 电商 | 满屏促销红、闪烁动效 | 价格层级清晰、库存与优惠券入口不藏 |
| 工具 | 装饰性插画、启动动画 | 首屏直达功能，减少中间页 |

> 注：涨跌配色遵循中国习惯 —— 涨用红 `#E34D59`，跌用绿 `#00A870`，
> 与欧美市场相反。做股票、基金、行情类时必须这样，否则用户会读反。

## 六、动效

小程序里动效只有一个作用：**告诉用户「你的操作有反应了」**。

```css
/* 点击反馈：用 hover-class，不用自己写动画 */
<view class="card" hover-class="card--active" hover-stay-time="80">
.card--active { background:#F2F3F5; }

/* 过渡：150-250ms，超过 300ms 就显得卡 */
transition: all 200ms ease-out;

/* 只在两处值得做进场动画：列表首屏、底部弹层 */
```

不要做：页面切换的转场动画（系统已经有了，自己加会冲突）、
无限循环的呼吸灯、按钮的弹簧回弹。

## 七、AI 自查清单

写完一个页面，逐条过：

- [ ] 一屏只有一个实心主色按钮？
- [ ] 正文 ≥ 28rpx？辅助文字 ≥ 24rpx？
- [ ] 所有可点元素 ≥ 88rpx？
- [ ] 灰色文字在白底上肉眼能看清？
- [ ] 左右边距都是 32rpx？
- [ ] 圆角只有两档？
- [ ] 阴影只有一档且朝下？
- [ ] 长段落左对齐？
- [ ] 空态有图标 + 人话 + 出口？
- [ ] 底部固定栏留了 `env(safe-area-inset-bottom)`？

十条全过，这个页面就不会显得廉价。
