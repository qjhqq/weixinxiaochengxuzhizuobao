# 阶段 5 · 内容与冷启动素材

> **这一步和阶段 4 并行做。** 上线时是空壳，是独立开发者最常见的死法。

---

## 先给结论

**内容不是「上线后慢慢补」，是上线的前置条件。**
一个查询类/知识类小程序，首批至少 **30 条**才有「能查到东西」的感觉；记录类至少要有 **3 篇**科普或引导。

---

## AI 要做的事

### 1. 定内容形态（先问清楚）

```
你的内容是哪种？
A. 预置库（固定条目，用户来查/看）→ 需要攒够量
B. 用户自己产生的数据 → 需要设计"月报/趋势"这类二次加工
C. 两样都有
```

### 2. 生产内容的三步法（合规版）

个人主体不能做生成式 AI，但可以做「AI 起草 + 人工审定 + 入库检索」：

1. **AI 起草**：按统一结构生成初稿（标题 / 一句话结论 / 3 条要点 / 注意事项）
2. **人工审定**：你（用户）逐条改成自己的话。**这一步不能省**，这是你和纯 AI 内容的区别
3. **入库**：结构化存进云数据库，前端做检索匹配

检索式问答的最小实现：
```js
// 关键词命中 + 简单打分，够用
score = 命中关键词数 * 2 + (标题包含 ? 3 : 0) + (标签匹配 ? 2 : 0)
// score < 阈值 → 走兜底话术，不要硬答
```

**兜底话术很重要**：「这个问题我还没收录，你可以换个说法，或者看看这几条相关的」——比乱答一个答案安全得多。

### 3. 设计「回头理由」

内容的价值不在「有」，在「会更新」。至少设计一个：
- 每周新增 N 条
- 按用户数据生成月报
- 节气/季节/年龄段相关的定期内容

### 4. 冷启动素材（可选，但强烈建议）

用户如果打算发抖音/小红书，这里直接给素材（见 `06-抖音投放/`）：
- 60 秒口播脚本（3 个版本）
- 封面文案
- 置顶评论

## 要产出的文件

`我的项目/07-内容库.md`（首批内容清单）+ 内容本身存数据库或 JSON。

内容条目统一结构：
```
标题：
一句话结论：
要点 1 / 2 / 3：
注意事项 / 免责声明：
标签：标签1, 标签2
来源：（如果引用，必须写清）
```

## 出门检查

```
阶段 5 出门检查：
✅ 内容形态已确认
✅ 首批内容 ≥ 30 条（查询类）或 ≥ 3 篇（记录类）
✅ 每条都有免责声明（涉及健康/法律/财务必加）
✅ 检索兜底话术已写
✅ 有至少一个"会更新"的机制
```

---

## 常见坑

- **直接用 AI 生成的内容上线** —— 事实错误率不低，且出了事是你担责。
- **内容没有标签** —— 检索匹配效果差一半。
- **健康/医疗内容给结论** —— 必须写「仅供参考，不构成诊断」，涉及治疗/手术要提示就医。
- **把「AI 智能问答」写进名称或简介** —— 个人主体命中生成式 AI 类目，直接拒。
