## 先给结论

**默认技术栈：微信原生小程序 + 微信云开发。**
不用 Taro/uni-app，不自建服务器，不接第三方后端。

理由：一个人的项目，**运维成本 > 开发成本**。云开发把服务器、数据库、存储、鉴权全包了，免费额度够一个早期产品用。

**例外**：你已经会 React 且要做多端 → 用 Taro，但要知道多端会带来 30% 额外调试成本。

### 2. 定目录结构

```
miniprogram/
├── app.js / app.json / app.wxss
├── pages/
│   ├── index/        首页
│   ├── record/       记录
│   ├── detail/       详情
│   ├── mine/         我的
│   └── privacy/      隐私政策
├── components/       自定义组件（按需）
├── images/           图片（tabBar 图标必须是 PNG）
└── utils/
    ├── api.js        云函数调用封装（统一错误处理）
    ├── format.js     日期/数字格式化
    └── storage.js    本地缓存封装
cloudfunctions/
├── api/              统一业务入口（action 路由）
└── init/             建集合（幂等）
```

**云函数用「一个入口 + action 路由」**，不要一个功能一个云函数 —— 云函数数量多起来，部署和权限管理会很痛苦。

```js
// cloudfunctions/api/index.js 骨架
exports.main = async (event) => {
  const { action, data } = event
  const routes = { addRecord, listRecords, getRecord, removeRecord }
  const fn = routes[action]
  if (!fn) return { code: 400, msg: `unknown action: ${action}` }
  try {
    return { code: 0, data: await fn(data, event) }
  } catch (e) {
    console.error(action, e)
    return { code: 500, msg: '服务异常，请稍后重试' }
  }
}
```

### 3. 设计数据模型（最容易埋雷的一步）

对每张表，必须写清四件事：

| 项 | 说明 |
|----|------|
| 集合名 | 小写复数，如 `records` |
| 字段 | 字段名 / 类型 / 是否必填 / 示例值 |
| 权限 | 仅创建者可读写 / 所有人可读 / 仅管理端 |
| 索引 | 哪个字段常查，就建索引 |

**通用字段约定**（每张表都加）：
```js
{
  _openid: '自动写入，不要手动存',   // 云开发自动加
  createdAt: Date.now(),            // 时间戳，别用字符串
  updatedAt: Date.now(),
  deleted: false                    // 软删除，别真删
}
```

**三条铁律**：
1. **时间存时间戳，不存字符串**。「2026-10-30」这种字符串排序和范围查询都会翻车。
2. **权限默认「仅创建者可读写」**，需要公开的单独放开，不要反过来。
3. **软删除**。用户误删、你要做数据恢复、要统计，都靠这个字段。

### 4. 列云函数清单和外部依赖

| 能力 | 实现方式 | 注意 |
|------|---------|------|
| 数据读写 | 云数据库（前端直连） | 简单查询前端直接查，复杂逻辑走云函数 |
| 文件上传 | 云存储 | 前端 `wx.cloud.uploadFile` |
| 第三方 OCR | 云函数转发 | 密钥走环境变量，超时调大 |
| 定时任务 | 云函数定时触发器 | 记得写幂等 |
| 消息推送 | 订阅消息 | 必须用户主动点击触发 |

**云函数超时**：默认 3 秒。涉及外部 API（OCR、大模型）的必须调到 **20 秒以上**，否则前端表现是「一直转圈、无任何返回」。

## 常见坑

- **表设计时没想「以后要加什么」** —— 至少留一个 `extra: {}` 字段存扩展数据，比以后改表结构省事。
- **前端直连数据库做复杂查询** —— 云数据库查询能力有限（不支持复杂聚合），复杂统计放云函数。
- **一个功能一个云函数** —— 部署 20 个云函数后你会想哭。用 action 路由。
- **忘了建索引** —— 数据过千条后列表加载明显变慢。
- **`_openid` 手动存** —— 云开发自动写入，你手动存会冲突。
