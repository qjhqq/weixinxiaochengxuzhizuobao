# 阶段 1 · 产品策略与 MVP

> **这一步的目的**：把「我想做个小程序」变成「一个有边界、能验收、两周能做完的东西」。
> 产出不是商业计划书，是一张**功能取舍表**。

---

## 先给结论

一个人的项目，**功能数量是最大的敌人**。你的目标不是做全，是做完。
能上线的最小版本，通常只有 5-8 个页面。

---

## AI 要做的事

### 1. 定北极星指标（只选一个）

一次只问一个问题，给 4 个选项：

```
这个产品做成了，你最想看到哪个数字涨？
A. 用的人多（DAU / 新增）
B. 用的人反复回来（7 日留存 / 每周使用次数）
C. 每个人用得很深（单次时长 / 记录条数）
D. 有人愿意付钱（付费率）
```

选完，帮他把它翻译成一句可测的话，例如：
> 北极星：**每个建档用户每月至少记录 2 次**。所有功能都要回答「它能不能推高这个数」，答不上来的砍掉。

### 2. 四层漏斗拆功能（每层不超过 3 个）

| 层 | 问什么 | 典型功能 |
|----|--------|---------|
| L1 获客 | 有没有不用注册就能体验的钩子？ | 拍照即出结果、单题测算、免费查一次 |
| L2 留存 | 有什么理由让他下周还来？ | 提醒、月报、连续记录天数 |
| L3 价值 | 数据攒够了能产出什么独家内容？ | 趋势图、同龄对比、年度总结 |
| L4 商业 | 以后怎么收钱？（先想不做） | 会员、增值报告、引流到店 |

**规则**：L1 和 L2 必须有，L3 做一个，L4 只写进文档不实现。

### 3. 砍 MVP（最重要的动作）

拿功能清单，逐条问四个问题，任何一个答「是」就砍：

1. 没有它，用户能完成核心动作吗？（能 → 砍）
2. 它需要新的资质/类目吗？（需要 → 砍或换）
3. 它需要用户之间互动吗？（需要 → 砍）
4. 它能让用户"今天就看到东西"吗？（不能 → 排到 v2）

砍完目标：**5-8 个页面，1 个核心动作，1 个留存理由。**

### 4. 写清楚「不做什么」

这一节比「做什么」更重要。写 3-5 条，例如：
- 不做社交，不做评论
- 不做付费，v1 全免费
- 不做多端，只做微信小程序
- 不做后台管理系统，用云开发控制台顶

---

## 要产出的文件

`我的项目/03-产品策略.md`，用 `02-模板/产品策略.md`。必须包含：

1. 一句话定位：**给【谁】解决【什么麻烦】，靠【什么】让他回来**
2. 北极星指标（一个，可测）
3. 四层功能表（每层 ≤3 个，标注 v1 / v2）
4. 不做什么（3-5 条）
5. MVP 页面数（数字）

---

## 出门检查

```
阶段 1 出门检查：
✅ 北极星指标是一个可测的数字，不是"提升体验"
✅ L1 有一个免注册钩子
✅ L2 有一个留存理由
✅ MVP 功能 ≤ 8 个，且每个都能在阶段 0 的能力清单里找到对应
✅ 写清了"不做什么"
```

⚠️ 如果 MVP 超过 10 个功能，说明你砍得不够，回去再砍。

---

## 常见坑

- **北极星选「用户数」** —— 一个人做的小程序，早期用户数取决于你发多少视频，不取决于产品。选留存类指标更可控。
- **钩子功能要注册才能用** —— 获客漏斗直接断在第一屏。
- **留存靠推送** —— 订阅消息必须用户主动点，不能诱导，别把它设计成唯一留存手段。
- **L4 商业想太多** —— 个人主体连支付都开不了，先别设计会员体系。
- **把「AI 生成」当卖点** —— 个人主体做不了，且用户对生成内容的信任度低于「专业整理过的库」。
