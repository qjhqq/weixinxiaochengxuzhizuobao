# 阶段 4 · 开发与联调

> **这一步的目的**：一页一页做完。
> 你（用户）的工作是**验收**，不是写代码。AI 的工作是**写 + 自己测 + 汇报**。

---

## 先给结论

**开发顺序决定返工次数。** 固定按这条线走：

```
骨架 → 跑通一条最短链路 → 补页面 → 补状态 → 美化 → 真机
```

最短链路 = 「用户能完成一次核心动作」的最小路径。例如记录类：
`首页 → 填一次 → 存进数据库 → 列表能看到 → 点进去能看详情`

**这条链路跑通之前，不要做任何第二功能，不要美化。**

---

## AI 要做的事

### 1. 开工前先建骨架（一次做完）

- `app.json` 配好 pages、window、tabBar
- `app.wxss` 写进设计 token + 基础类（容器、卡片、按钮、文字层级）
- `utils/api.js` 写好云函数调用封装（统一 loading、统一错误提示、统一 code 判断）
- `cloudfunctions/init` 写一个**幂等**的建集合 action，能在测试面板一键初始化
- 跑一次 `04-工具/check.js`，确认骨架没有红线问题

骨架做完让用户**在开发者工具里打开看一眼**，确认能启动、不报错，再往下。

### 2. 一页一页做，每页固定四步

1. **先写静态结构**（WXML + WXSS，用假数据），让用户看长相
2. 用户确认长相 → **接数据**
3. **补三态**：空态 / 加载态 / 失败态
4. 跑校验 + 让用户真机点一遍

**一次只交一个页面。** 不要一口气给 5 个页面然后让他找 bug。

### 3. 每轮改动的汇报格式（固定）

```
改完了：首页记录卡片
- 改了什么：卡片高度 160→180rpx，加了趋势箭头
- 根因（如果是修 bug）：列表复用了详情页的 class，padding 被覆盖
- 校验：check.js 通过，0 个红线
- 你要做的：在开发者工具里点一下首页，看卡片高度对不对
```

**说完「改完了」必须给出「你要做的」**——一句具体的验收动作，不要让他自己想怎么验。

### 4. 调试点哪

| 现象 | 先查什么 |
|------|---------|
| 白屏 / 样式全丢 | WXSS 里有没有 `var(`（不支持 CSS 变量） |
| 顶部被导航栏挡住 | 是不是用了全局 `.page` 类（带负边距） |
| 换了图还显示旧图 | 换文件名 + 完全退出开发者工具再重开 |
| 云函数无返回、一直转圈 | 超时没调大（默认 3s）；看云函数日志最后一条 |
| `Cannot find module './xxx'` | 新增的文件没上传，重新整体上传该云函数 |
| 数据库查不到数据 | 集合权限（仅创建者可读写会让你查不到别人的数据） |
| 模拟器正常真机异常 | 相机/扫码/订阅消息必须真机测 |
| 上传图片失败 | 双入口（拍照/相册）有没有都实现；权限有没有申请 |

### 5. 每天的节奏（给用户看的）

```
今天目标：把"记录"页做完（预计 1.5 小时）
1. 我做：静态结构 + 接数据库（20 分钟）
2. 你做：在开发者工具里点一遍，截图给我（5 分钟）
3. 我做：按截图改（20 分钟）
4. 你做：真机点一遍（5 分钟）
收工：更新 PROGRESS.md
```

不要让用户一天面对「把整个小程序做完」这种目标。

## 编码纪律（AI 自查）

- **不写死数据**：假数据用完就删，不要留在代码里当 fallback
- **不吞异常**：`catch` 里必须 `console.error` + 给用户可读提示，不许空 catch
- **不硬编码密钥**：全部走云函数环境变量，代码里只留占位符
- **不重复样式**：三个页面以上重复的样式提到 `app.wxss`
- **不留 TODO 不记账**：写了 `// TODO` 就在汇报里列出来
- **不擅自加功能**：用户没说的功能，建议就好，不要直接写进去

## 常见坑

- **先做登录再做功能** —— 登录会挡住你测所有功能。先做免登录版本，最后再加。
- **在模拟器上验收 UI** —— 模拟器的字体、圆角、安全区都和真机不同。
- **一次改 10 个文件然后一起测** —— 出问题时不知道是哪个改动导致的。
- **图片没压缩就上传** —— 超过 200KB 会报警告，包体积也会超限（主包 2MB）。
- **忘记处理「用户拒绝授权」** —— 相机权限被拒后要有引导去设置的文案，否则用户以为坏了。
