# 七阶段（速查版）

> 完整版在开工包的 `01-阶段包/`（每阶段一份手册）。这里是压缩版，
> 目的是**技能单独装在全局、手边没有包时也能跑完流程**。冲突时以包里完整版为准。

## 共同规则

- 阶段开始：一句话说清「现在进阶段 X，要做的是…，预计…」，然后只问 **1-3 个必须他决定**的问题。
- 阶段结束：产出落成文件 → **逐条打勾**念给他听 → 更新 `PROGRESS.md` → 一句话播报下一阶段。
- 门不是「感觉差不多了」，是「文件存在 + 条目齐全」，必须能客观打勾。
- 允许跳阶段，但在 `PROGRESS.md` 备注写「跳过阶段 X，原因：…」，并在后面补回来。
- 阶段 4 之前**不写业务代码**。

---

## 阶段 0 · 合规与主体（0.5 天）

**做什么**

1. 问主体：个人 / 个体户 / 公司 / 不确定。
2. 逐项判定敏感功能：支付收款、用户发布内容、医疗健康、教育培训、AI 生成、直播、web-view 跳转。
3. 给结论：个人主体通常做不了 **AI 生成、支付、直播、web-view 外跳**；医疗/金融/教育/招聘/社交等类目需要资质。
4. 给 1 个主选类目 + 1 个备选，让他去微信后台确认是否可选。

**产出**：`我的项目/00-能力清单.md`（能做 / 不能做 / 要什么资质 / 类目初选）

**门禁**

- [ ] 主体类型已确认
- [ ] 7 类敏感功能逐项判定过
- [ ] 类目有主选 + 备选
- [ ] 明确写了「哪些功能这个主体做不了」

**不过门**：做完才发现上不了架，前面全白干。这是唯一一个做错要推倒重来的阶段。

---

## 阶段 1 · 产品策略（0.5 天）

**做什么**

1. 定**一个**北极星指标（例如「7 日内重复记录的人数」），不要三个。
2. 画四层漏斗：曝光 → 进入 → 完成核心动作 → 再次使用。每层写一个可测的数。
3. 砍 MVP：页面压到 **3-5 个**，明确写出「这一版不做什么」。

**产出**：`我的项目/02-产品策略.md`

**门禁**

- [ ] 北极星指标一句话，可测
- [ ] 四层漏斗每层有指标
- [ ] MVP 页面 ≤ 5 个
- [ ] 明确列出「本期不做」的清单

**不过门**：功能越做越多，永远上不了线。

---

## 阶段 2 · 设计（1-2 天）

**做什么**

1. 页面清单：每页写清 **入口 / 出口 / 主按钮**，没有出口的页面不能存在。
2. 定设计 token：字号 6 档、间距 8 的倍数、圆角 3 档、主色 1 个。数值见 `design.md`。
3. 三个状态：空态、加载态、错误态，每页都要想一遍。
4. 用户说不清风格 → 报 3 套配色编号让他选，**不要让他描述颜色**。

**产出**：`我的项目/03-页面清单.md`、`我的项目/04-设计规范.md`，以及 `app.wxss` 里的 token 块

**门禁**

- [ ] 每个页面都有出口
- [ ] token 已写进 `app.wxss`，不是只写在文档里
- [ ] 三态覆盖到了所有列表页和表单页
- [ ] 全站只有 1 个主色
- [ ] 没有 `var(--x)`

**不过门**：边写边改样式，返工三遍。UI 返工成本是逻辑返工的 3 倍。

---

## 阶段 3 · 技术（0.5 天）

**做什么**

1. 技术栈定死：原生小程序 + 云开发 / 原生 + 自建后端。**不要在开发中途换**。
2. 数据模型：集合名、字段、类型、索引、谁能读谁能写。
3. 云函数清单：名字、入参、出参、超时时间。

**产出**：`我的项目/05-数据模型.md`

**门禁**

- [ ] 每个页面要展示的数据，都能在模型里找到来源
- [ ] 没想清的字段标了 `TODO`，不是留空
- [ ] 云函数数量和 MVP 需要一致，没有「先建着备用」
- [ ] 读写权限写过一遍（避免所有人可写）

**不过门**：写着写着发现表设计错了，测试数据要重录。

---

## 阶段 4 · 开发（1-3 周，弃坑率最高）

**每日循环（固定五步，别自由发挥）**

1. **开场**：读 `PROGRESS.md` 的开发日志，看昨天做到哪、卡在哪。
2. **只定今天一个页面**，说清「今天做 X 页，预计 40 分钟」。
3. **做**：静态结构 → 让他看长相 → 接数据 → 补三态。
4. **验收**：给一句具体动作，「在开发者工具里点首页右上角，看数字有没有加 1」。
5. **收工**：跑体检脚本，把结果和进度写进开发日志，**写清明天从哪开始**。

**三条硬规矩**

- 一天不推进两个页面，除非他明确说「今天多做点」。
- 连续两天没进展 → 主动砍范围：删掉一个页面，告诉他「少一个也能提审」。
- 页面做完不要立刻美化，先把最短链路整条跑通，再统一调样式。

**门禁**

- [ ] 最短链路（进 → 做 → 看到结果）能完整跑通
- [ ] 所有页面能进能出，没有死路
- [ ] 体检脚本 0 error
- [ ] 真机走过一遍，不只看模拟器

---

## 阶段 5 · 内容与冷启动（与 4 并行）

**做什么**

1. 列出「首屏必须有内容」的位置，逐条填。
2. 首批内容 20-50 条，或者设计一个「用户自己第一条内容」的引导。
3. 准备 1 个可分享物（卡片、报告、对比图）。

**门禁**

- [ ] 首屏不空
- [ ] 新用户 30 秒内能完成一次核心动作
- [ ] 有 1 个能发朋友圈的东西

**不过门**：上线是空壳，来了人留不住。

---

## 阶段 6 · 提审与上线（1-3 天）

**做什么**

1. 提审自检表逐条过（技能 `references/review-checklist.md`）。
2. 隐私政策可访问、内容与采集字段一致。
3. 提审 → 被拒 → **先分类**（类目 / 资质 / 内容 / 技术）→ 再改 → 再提。

**门禁**

- [ ] 自检表全绿
- [ ] 隐私政策能从首页两步内打开
- [ ] 所有「邀请好友 / 分享」有真实内容
- [ ] 没有测试数据、假按钮、TODO 文案

**被拒时的第一条纪律**：不要先改 UI。类目问题改代码没用。

---

## 时间预期（一个人 + AI）

| 你的情况 | 现实预期 |
|---|---|
| 完全不会代码，每天 2 小时 | 4-6 周到能提审 |
| 会一点，周末集中做 | 2-3 周 |
| 会前端，全职 | 1 周内 |

**不要承诺「三天上线」。** 三天能做出 demo，做不出能过审的产品。
