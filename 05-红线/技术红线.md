# 技术红线

> 每一条都来自真实踩坑。**写代码前读一遍，改到相关区域时回来看。**
>
> 最后核对：2026-10 ・ 适用于微信开发者工具稳定版 / 基础库 3.x
> 技术红线不像审核规则变得那么快，但「工具行为」类（图片缓存、云函数超时）会随版本变。
> 遇到和这里写的不一样，先信你眼睛看到的，然后回来改这一份。

## 一、样式层

### 1. WXSS 不支持 CSS 变量

- **现象**：写了 `color: var(--brand)`，整页样式全丢或变白。
- **根因**：小程序 WXSS 没有 CSS Custom Properties。
- **纪律**：设计 token 定好后立刻展平成字面值；全项目搜 `var(` 应为 0 结果。
- **自查**：`node check.js` 会直接报。

```css
/* 错 */
.btn { background: var(--brand); }

/* 对 */
.btn { background: #2B6DE5; }  /* token: brand */
```

### 2. 全局 `.page` 的负边距只能给沉浸式页面用

- **现象**：原生导航栏页面顶部内容被导航栏挡住；或整页盖住 fixed 底部栏、输入框点不动。
- **根因**：全局 `.page` 常带 `margin-top: -112rpx`（让内容上浮盖住头部）和 `z-index: 1; position: relative`（盖住 fixed 元素）。
- **纪律**：只有 `navigationStyle: custom` 且顶部有沉浸式大图的页面能用 `.page`；其余页面用独立容器类（如 `.np`）。fixed 栏配 `z-index: 100`。
- **自查**：`node check.js` 会按 app.json 的 `navigationStyle` 逐页判断。

### 3. 图片尺寸与格式

- 单图 > 200KB 触发警告；PNG 照片转 JPEG（q85）通常省 70%。
- tabBar / 导航图标必须是 PNG（透明底）。
- 主包上限 2MB，超了要分包或把图片放云存储。

## 二、开发者工具

### 4. 同名图片缓存极顽固

- **现象**：图换了，工具里显示的还是旧的。
- **解法**：换图必须**换文件名**（`icon_v2.png`）；tabBar 图标这类同名替换要**完全退出工具**（任务管理器杀进程级）再重开。
- 这一条会浪费你半小时，而且每次都以为是代码问题。

### 5. 模拟器 ≠ 真机

- 相机、扫码、订阅消息、分享、安全区，模拟器和真机行为都不同。
- 上传类功能做**双入口**（拍照 / 从相册选择），并在真机过一遍。

### 6. 缓存清了还是旧的

按顺序试：清编译缓存 → 清全部缓存 → 关掉「不校验合法域名」看看 → 重启工具 → 换文件名。
实在不行，删掉 `miniprogram_npm` 重编译。

## 三、云开发

### 7. 云函数默认 3 秒超时

- 涉及外部 API（OCR、大模型）必须调到 **20 秒以上**，写在 `config.json`：
```json
{ "timeout": 20 }
```
- 症状：前端一直转圈，云函数日志里有结果但前端收不到。

### 8. 密钥管理

- 第三方 Key 一律走**云开发控制台 → 云函数 → 环境变量**。
- 代码里只允许 `process.env.XXX || ''`。
- 部署方式：新增了文件（如 `ai-config.js`）必须**整体上传该云函数目录**，只传 index.js 会报 `Cannot find module`。

### 9. 集合初始化要幂等

- 写一个 `initCollections` action，可以重复执行不报错：

```js
const COLLECTIONS = ['records', 'users']
for (const name of COLLECTIONS) {
  try { await db.createCollection(name) } catch (e) { /* 已存在，忽略 */ }
}
return { code: 0, data: 'ok' }
```

- 顺便在这里把索引建好，比在控制台手点不容易漏。

### 10. 数据库权限

- 默认「仅创建者可读写」，要公开的字段单独设计（比如把公开内容放另一张表）。
- 权限设错的表现：自己测能查到，换个人就查不到（或能看到别人的）。

## 四、AI 协作

### 11. AI 生图必须人工确认

- 生成图先发给用户看，他说行才接入项目。
- 含文字、字母、精确图形的画面（视力表、刻度、图表）**AI 必错**，用代码画（Canvas 或 Python Pillow 按坐标画）。
- 素材要去重，不要攒一堆相似图。

### 12. 不让 AI 猜参数

- 文档、密钥、模板 ID、AppID 必须用户提供或从项目文件读。
- 缺失时**问**，不要编一个占位值填进去然后假装跑通了。

### 13. AI 报「已完成」时要求给证据

- 要求它给出：改了哪些文件、跑了什么校验、用户要点哪里验收。
- 只说「已优化」没有证据的，八成没改或改错了。

## 五、合规

### 14. 个人主体能力边界

- 过不了生成式 AI / 深度合成类目；禁 web-view、外部跳转；不能开支付、直播。
- 变通：预置内容库 + 检索式问答；模板 + 规则拼装代替生成。
- 涉及未成年人信息：隐私政策单独成章 + 页面显眼同意按钮 + 同意状态落盘。

### 15. 医疗/健康类表述

- 所有输出标注「仅供参考，不构成诊断」。
- 涉及治疗、手术的问题，必须提示就医，不能给方案。
- 不要在小程序名称、简介里出现「诊断」「治疗」「AI 医生」。

### 16. 开源/分享前脱敏

- 全项目搜：`AKID`、`sk-`、`secret`、`api_key`、`appid`、真实域名、真实公司名。
- 云环境 ID 也要去掉，别人用不了还会暴露你的资源。
